# Reliquary

A gothic crimson-and-black native iPhone client for [Immich](https://immich.app). SwiftUI, iOS 17+, no third-party packages. Bundle id `com.ross.reliquary`.

## Features

- Sign in with a server URL and API key (key stored in the Keychain, sent as `x-api-key`). The URL can be entered as `host`, `https://host/`, or `https://host/api`; a trailing slash and `/api` suffix are stripped.
- Timeline grouped by month, with a lazy 3-column grid and infinite scroll
- Full-screen viewer with swipe between items, pinch-zoom and double-tap zoom, and video playback
- Albums (owned and shared) and album detail
- Smart search (CLIP) using a text description
- Upload photos and videos from the camera roll
- Image cache: `NSCache` for decoded images plus a 1 GB `URLCache` on disk

The app is always dark. Theme colours live in `Reliquary/Theme/Theme.swift`.

## Build

The project is generated by XcodeGen from `project.yml`. `_stark_builder.ps1` creates `build-and-publish.sh` and the Codemagic workflow automatically. Use the normal push-and-build flow.

## Immich API endpoints used

All requests go to `<server>/api/...` with the `x-api-key` header.

| Purpose | Endpoint |
|---|---|
| Validate key | `GET /users/me` |
| Timeline | `POST /search/metadata` with `{page, size:200, order:"desc"}`; follows `assets.nextPage` |
| Album list | `GET /albums` and `GET /albums?shared=true` |
| Album detail | `GET /albums/{id}`; if it returns no assets but `assetCount > 0`, falls back to `POST /search/metadata` with `albumIds` |
| Smart search | `POST /search/smart` with `{query, page:1, size:200}` |
| Thumbnails / previews | `GET /assets/{id}/thumbnail?size=thumbnail\|preview` |
| Video | `GET /assets/{id}/video/playback` (API key sent via `AVURLAssetHTTPHeaderFieldsKey`) |
| Upload | `POST /assets`, multipart: `deviceAssetId`, `deviceId`, `fileCreatedAt`, `fileModifiedAt`, `isFavorite`, `assetData` |

## Assumptions and version tolerance

- **Timeline uses `search/metadata`, not `timeline/buckets`.** It is simpler and works across a wider range of Immich versions. It does not use server-side month buckets, so the full timeline loads page by page (200 assets per request) and grouping happens on the device.
- If a server rejects the `order` field with HTTP 400, the request is retried without it, and the app sorts by date locally anyway.
- Thumbnails fall back to the legacy `GET /asset/thumbnail/{id}?format=WEBP|JPEG` path on a 404.
- Video playback uses only the current `/assets/{id}/video/playback` path. Servers old enough to lack it (the legacy path is `/asset/file/{id}`) are not supported for video.
- `nextPage` may be a string, a number or null; all three are handled. All model fields except ids are optional and unknown keys are ignored.
- Uploads treat a response `status` of `duplicate` as success ("Already in your archive").
- The API key needs enough permissions for `users/me`, assets, albums and search. A key with all permissions is simplest.
- `NSAllowsArbitraryLoads` is on so plain `http://` servers on a LAN or Tailscale address work.

## Known limits

- Archived, trashed and locked assets are whatever `search/metadata` returns by default (normally excluded).
- No delete, favourite, share-link or People/Places screens.
- Upload is foreground only; it does not continue if the app is suspended.
